# v0.4 GPU stream acceptance

## Purpose

Use this same procedure for the Codex and DeepSeek implementation branches. Results describe product behavior; they are not a model scorecard. A final build may combine the strongest verified components from both branches.

## Fixed test conditions

Record before every run:

- branch and full commit ID;
- portable package SHA-256;
- Windows, Codex, Wallpaper Engine and GPU driver versions;
- CPU, GPU, hardware encoder/decoder and display refresh rate;
- display resolution, Windows scale, Codex viewport and capture resolution;
- selected backend, requested FPS, render scale and fit/focus settings;
- Workshop IDs only for locally installed manual cases. Never attach or commit their media.

Use the same machine, Codex build, Wallpaper projects and settings for both implementations. Start each measured run from a normal clean launch, not a debugger.

## Required workloads

1. A redistributable synthetic 60 FPS motion fixture for repeatable cadence, stale-frame and visual-continuity checks.
2. Makima (`2935530316`) for composition, sharpness, motion and stability.
3. Saki (`2914257158`) for complex Scene motion; pointer interaction is not required.
4. Pastel (`3494484288`) for composition, color and overlay behavior.
5. At least three additional locally installed Scene projects previously observed to crop, blur, flash or stall.
6. Existing local image and ordinary video cases for regression coverage.

## Hard product gates

### Rendering and cadence

- On capable hardware, the synthetic 1920×1080 60 FPS case selects the GPU backend and sustains a 60 FPS target without using per-frame JPEG/Base64/CDP transport.
- Report observed capture, encoded and presented cadence separately. For a true 60 FPS source, the 10-minute run must average at least 55 presented FPS, with no unexplained sustained interval below 50 FPS longer than two seconds.
- A 30 FPS fallback must average at least 28 presented FPS and must be visibly labeled as fallback.
- Below 30 FPS is degraded, not full success. The UI must diagnose it and may offer or select a lower render scale.
- The reported capture resolution must match the configured scale; preview thumbnails cannot count as native success.

### Continuity and correctness

- No periodic flash, unintended transparent/black/gray replacement, severe blur, color corruption or unexplained disappearance during each 10-minute case.
- A recoverable interruption retains the last confirmed good frame until a new frame is presented or an explicit labeled fallback is selected.
- Source composition and aspect ratio are preserved at the tested fit/focus settings.
- A lower-FPS source is reported honestly and is not failed solely for lacking 60 unique source frames.

### Switching and ownership

- Complete 50 consecutive Scene switches across at least five projects.
- Every successful switch must present a new frame from the selected project before retiring the prior stream.
- No frame from an earlier project may reappear after promotion of the new stream.
- Repeated switches must not leave capture, encoder, transport, decoder, hidden worker or Wallpaper Engine window resources growing without bound.
- Restore and application exit close all resources owned by the current session.

### Recovery and visibility

- Exercise capture interruption, encoder initialization failure, transport disconnect and presenter/decode timeout with synthetic fault injection.
- Recovery is bounded, diagnosed and cancellable; it cannot create competing retry loops.
- The private Wallpaper Engine render window never appears in the taskbar or Alt+Tab and never takes foreground focus while remaining capturable.
- If Wallpaper Engine is unavailable, a Scene receives a clear requirement/fallback message rather than a false success state.

### Existing-feature regression

- Search uses custom and original names correctly.
- Rename, restore name, personal collection and type filtering persist safely.
- Image/video wallpapers, fit/focus and color/readability settings still apply.
- queued apply, safe normal restart, startup restore and explicit Restore behave as documented.
- Application projects remain rejected.
- No installed Codex files or Workshop projects are modified.

### Build, safety and packaging

- Release build, self-tests, runtime smoke test and repository hygiene checks pass.
- The portable package runs from a fully extracted directory and has a matching SHA-256 file.
- New binary/media dependencies have documented origin, version, license and redistribution terms.
- No private/copyrighted fixtures, captured frames, user state, credentials or build artifacts are committed.

## Decision categories

- **Pass — GPU 60:** all hard gates pass on the 60 FPS GPU path.
- **Pass — GPU 30 fallback:** fallback is correctly labeled and all applicable 30 FPS, continuity and safety gates pass.
- **Compatibility only:** reduced-frame-rate JPEG/static fallback works but the GPU video path does not meet its gate.
- **Fail:** black/gray flashes, stale wallpaper recurrence, switching deadlock, hidden-window exposure, unbounded resource growth, false status or safety regression occurs.

Final convergence must cite evidence for every adopted component. A branch-level pass does not require adopting that branch wholesale.
